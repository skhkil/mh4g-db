# MH4G PC·모바일 세팅 동기화

기존 GitHub Pages 시뮬레이터와 Cloudflare Workers + D1를 사용한다. **Cloudflare Tunnel과는 별개**이며, Worker 주소는 웹 앱에 고정되어 있다.

## 현재 배포 환경
- 시뮬레이터: https://skhkil.github.io/mh4g-db/
- Worker: https://mh4g-sync.skhkil.workers.dev
- 상태 확인: https://mh4g-sync.skhkil.workers.dev/health
- D1 binding: `DB` → `mh4g-sync`, 테이블 `sync_records`
- 최초 설정 이후 **Worker 재배포 없이 프런트엔드 변경만으로** 저장 이벤트 동기화를 개선했다.

## 사용
1. PC에서 시뮬레이터 → **☁ 세팅 동기화** → **새 연결 만들기**.
2. 43자리 연결 코드를 안전한 곳에 보관한다. 공개 금지.
3. 모바일에서 **☁ 세팅 동기화** → 코드 입력 → **기존 코드로 연결**.
4. 저장 세팅, 보유 호석, 발굴무기·방어구, 즐겨찾기, 제작 체크리스트/소재가 동기화된다.

## 동작 (2026-11-10)
- 장비 세팅 저장·삭제, 보유 호석/발굴장비 변경, 즐겨찾기/제작 기록 저장 직후 이벤트 발생.
- 짧은 연속 변경은 약 **0.4초**로 묶어 서버에 자동 업로드한다.
- 다른 기기는 **약 10초마다** 서버 변경 확인; 앱 탭에 돌아왔을 때도 즉시 확인한다.
- 다른 기기 변경 수신 후 **화면 자동 새로고침**. 입력 중이거나 동기화 창이 열려 있으면 작업을 방해하지 않도록 새로고침을 잠시 미룬다.
- 백그라운드 모바일 브라우저는 타이머가 제한될 수 있다. 탭을 다시 열면 확인한다.
- 서버 연결 실패 시 로컬 저장을 유지하며 다음 확인 시 재시도한다.
- 양쪽 기기에서 동시에 편집하면 무단 덮어쓰기를 막고 **충돌 해결**을 요구한다.
- 기존 저장 데이터와 연결 코드는 변경하지 않는다.
- 이는 웹소켓 푸시가 아닌 **저장 즉시 업로드 + 10초 폴링 방식**이므로 다른 기기에 0초 지연으로 표시되는 완전한 실시간 시스템은 아니다.

## 동기화 복구 UI 보강 (2026-11-13)
- **상시 동기화**: 처음 연결은 1회지만 업로드는 데이터 변경 때마다, 다운로드 확인은 약 10초마다 반복된다. 일회성 호석 URL 가져오기와 별개다.
- 충돌·클라우드 누락으로 일시 정지되면 수동 '지금 동기화'도 아무 반응 없이 종료되던 문제를 수정해 오류와 '충돌 해결' 경로를 표시한다.
- **연결 진단** 버튼은 연결 코드 자체를 출력하지 않고 서버 접속/원격 기록 존재 여부/로컬·원격 리비전/로컬 수정 유무/자동 동기화 중지 여부만 보여준다.
- 원격 기록이 누락되었을 경우 **'충돌 해결' → '2'** 로 로컬 데이터를 클라우드에 복구할 수 있다. 해당 기기가 최신인지 반드시 확인하고 명시적으로 승인해야 하며, 로컬 백업은 보존한다.
- 클라우드가 존재하는 상태에서 '2'를 선택하면 서버 데이터를 덮어쓰므로 다른 기기 변경을 잃을 수 있다. '1'을 선택하면 서버 기준으로 복원하며 로컬 백업을 저장한다.
- 오류 발생 시 로컬 데이터 자체는 삭제하지 않는다. Workers/D1 실서비스 상태는 브라우저에서 연결 진단하여 확인해야 한다.

## PC/모바일 리비전 불일치 안전 진단 (2026-11-13)
- PC 리비전 45 / 모바일 리비전 3처럼 서로 다른 경우, **서로 다른 연결 코드**이거나 **동기화 충돌·네트워크 오류로 한쪽이 정지**한 상황을 우선 의심한다. 리비전만으로 어느 쪽이 최신 개인 데이터인지 단정하지 않는다.
- **연결 진단**에 코드 원문 대신 SHA-256 기반 12자리 연결 식별자가 표시된다. PC와 모바일 식별자가 같은지 우선 비교한다. 식별자와 로컬/원격 리비전, 로컬 변경 여부, 보유 호석/저장 세팅 개수, 서버 연결 결과를 볼 수 있다.
- 양쪽에서 **이 기기 데이터 백업(JSON)**으로 별도 백업한 뒤에만 전환·충돌 해결을 실행한다. 백업에는 동기화 연결 코드가 포함되지 않는다.
- 식별자가 다르면 최신 데이터가 있는 PC의 **코드 복사** 기능으로 얻은 43자리 전체 코드를 모바일에 입력하고 **기존 코드로 안전하게 전환**한다. 대상 클라우드 기록이 실제 존재해야만 전환되고, 병합 전 확인창을 거치며 기존 코드/데이터는 실패 시 보존된다. 개인정보에 해당하는 코드를 채팅으로 공유하지 않는다.
- 식별자가 같은데 리비전이 다르면 각 기기의 **연결 진단 결과**를 비교한다. 서버 통신 오류면 클라우드·네트워크부터 확인하고, 충돌이면 백업 후 어느 데이터가 최신인지 판단하여 해결한다. '충돌 해결 2'는 클라우드 덮어쓰기이므로 무작정 실행하지 않는다.
- 클라우드 서비스 외부 접근 제한으로 이 작업 당시 Workers/D1 실시간 응답은 직접 검증하지 못했다. 프런트엔드 코드 교체 및 구문검사는 완료했지만 기기 간 실제 동기화 성공 여부는 별도로 확인 필요.

## v74 · 모바일 연결 코드 덮어쓰기 수정 (2026-11-13)
- 증상: PC 버전 45, 모바일 버전 3에서 PC 코드로 모바일을 전환해도 모바일 식별자는 이전 그대로, 버전만 4로 증가.
- 원인: 이전 render()가 동기화 후 기존 연결 코드를 #mhSyncCode 입력칸에 다시 써서 사용자가 입력한 PC 코드를 덮어씀. 이전 안전 전환도 같은 입력칸을 참조하여 기존 모바일 코드로 다시 업로드할 수 있었음.
- 수정: 현재 코드 입력창은 읽기 전용, 새 전환 코드는 별도 #mhSyncSwitchInput 사용. 전환 직전 PC 식별자와 대상 리비전을 확인하고 같은 코드 전환을 거부.
- 안전성: 대상 코드를 명시적으로 api()에 전달. 대상 GET/PUT 성공 전에는 연결 설정을 바꾸지 않으며 실패 시 기존 연결 보존. 전환 전 로컬 백업 수행.
- 모의 검증: 모바일 이전 클라우드 리비전 4, PC 클라우드 45를 가정. 폴링 후 PC 코드 보존, 전환 후 PC 46, 모바일 옛 클라우드 4 유지, 양쪽 세팅 및 호석 병합 완료. JS 구문검사 통과. 실제 서비스 검증은 별도 필요.
- GitHub 커밋 447738a7e5f3ddbbabe95a5cfe585bdeeaf25e27, edce1192afcb98481b49451be8530b9dedfba8cd. index.html 캐시 버전 v9-safe-relink-input-20261113.
- 사용법: 기기별 JSON 백업 → 모바일 강력 새로고침 → 모바일 세팅 동기화에서 '전환할 다른 기기의 연결 코드' 별도 칸에 PC 코드 → '기존 코드로 안전하게 전환' → PC와 같은 대상 지문 확인 → 데이터 병합 승인 → 양쪽 연결 진단. 코드 원문은 채팅에 보내지 말 것.

## 보안/주의
- 연결 코드는 비밀번호에 해당한다. 코드가 노출되면 클라우드 데이터에 접근할 수 있다.
- DB에는 비밀 코드의 SHA-256 식별자와 일반 JSON 세팅이 저장된다. 민감정보는 저장하지 말 것.
- 초기 연결 시 기존 로컬 데이터와 클라우드 데이터를 병합하고 로컬 백업을 남긴다.
- 무료 플랜 사용량 한도 초과 시 요청이 실패할 수 있다.
- 실제 PC·모바일 연동은 사용자의 환경에서 추가 확인 필요. JS 문법 검사와 GitHub 코드 반영은 확인함.
